# 从试验 overlay 迁移到独立 relay 项目

此文件是迁移方案，不是已经执行的线上变更记录。现有云端与信创执行端继续使用原试验版本，本目录的增强版本需完成离线检查后单独部署。跳过开机验收不等于它已经验收通过。

## 执行端

在信创电脑单独放置 relay 项目，保留原本地 MCP、Wind 终端、SDK 和原生产数据目录。relay 私有配置中明确：

```json
{
  "mcp_root": "/absolute/path/to/existing/wind-terminal-mcp",
  "shared_profile": "/absolute/path/to/existing/wind-terminal-mcp/runtime"
}
```

上面只是新增字段示例，不是完整配置；原 url、token、data_directory 必须保留，不替换整个 worker.json。如果移动配置文件，先把相对 data_directory 解析为原来的绝对路径，避免误建空状态目录或忽略尚未完成的任务。

只有确认旧执行端没有在执行任务、没有待回传结果和没有待核查标记后，才暂停旧执行端、备份配置并切换服务 ExecStart 到新 relay 路径。保留原解释器和 SDK 环境，先验证外部 core 哈希、私有状态目录及共享锁，确保全机只有一个中继执行端。不能删除 halt/inflight 标记来让服务变绿。

旧 worker 结果缺少新计量字段时，新的监控会把对应计量标记为未知，不能据此补造历史用量。新监控只能从实际记录开始统计。

## 云端网关

在任务空闲后停止旧网关，备份原数据库、配置与程序。SQLite 启用 WAL 时，应在停机后连同数据库相关文件一起保留，或使用 SQLite backup API 生成一致备份。新项目读取同一配置和数据库，执行兼容的新增表迁移，不重建凭据、不运行 init 覆盖旧配置。

新管理员凭据另行生成、私下保管。管理员权限只用于查看统计；普通客户端与工作端凭据不能读取管理员接口。新增或撤销客户端后需按工具说明重载网关配置；不能把工作端 token 发给客户端。

回退时停止新网关，恢复旧程序及备份的配置；若需恢复旧数据库快照，先确认新版本运行期间没有新任务或结果会因此丢失，不在活跃服务上直接覆盖数据库。

## 客户端

每台设备领取自己的配置文件；不得把一个同事的凭据复制给整个团队。Mac 和 Windows 只安装客户端依赖，不安装或登录 Wind，也不上传管理员/工作端凭据。配置生成器只生成自己的 MCP 条目，不覆盖已有本地 MCP。

迁移后的初次验收分开记录：离线多客户端调度/计量、客户端注册、云端状态、一次有界真实 Wind 数据及回执。Windows 客户端实机验收与跨操作系统 CI 是两个状态，不把仅有配置生成测试称为 Windows 端到端成功。
