# 用量监控与设备管理

## 云电脑统一管理台（0.3.0）

已有网关可以单独更新 [Wind 中继管理台](../monitor/README.md)：下载 `wind-relay-console-0.3.0.zip`，在云电脑解压到新文件夹，双击 `Update.cmd`。更新只替换管理台并保留既有配置、数据库、日志和密钥，不升级或重启网关/执行端。继续沿用后台任务 `WindRelayMonitor`；桌面 `WindRelay-Console` 解锁管理，直接输入本机网址只读查看。

监控从本机 SQLite 读取状态并调用状态接口，不提交 Wind 查询。页面包括网关及公网入口、执行端心跳和模式、当前/最近任务、设备统计、24 小时分布与已有 7 天计量。旧试验版没有计量表时显示未知；在线心跳不证明 Wind 已登录。

设备管理使用单独的本机访问密钥、Host/Origin 校验和受限接口；新增、下载和撤销都不通过公网网关的管理员角色。只有本云电脑的管理入口可操作。修改先备份网关配置，复用管理命令的独占锁；队列非空或数据库不可读时拒绝修改；原 worker/owner 等凭据保留。添加/撤销后仍须暂停新任务、确认队列空闲并重载 `WindRelayGateway`，再在页面核对权限生效；管理台不强制结束网关、不取消或重做任务、不清故障标记。

支持滚动日志和诊断 ZIP 导出。页面打不开时使用桌面 `WindRelay-Diagnostics`。导出使用字段白名单，只含状态、错误类别及位置、任务元数据、版本和文件哈希；不包含 token、接入文件、参数、行情正文或原始异常消息。日志当前加三份轮换，总量约 4 MiB。离线导出不启动另一个写入器或服务。

这些入口属于独立 relay 0.1.0。迁移网关和执行端之后，新增的观测才会开始生效；当前已部署的旧试验版本不会因下载本项目自动获得新功能。

## 运行版本与旧网关升级

管理台 0.3.0 显示从本机运行服务获取的网关版本、构建号、队列策略与工具契约，可导出不含密钥的部署 JSON。旧网关不报告版本时保持未报告，执行端版本未核验时保持未知。网关升级包 `wind-relay-gateway-upgrade-0.1.2.zip` 的 `Upgrade-Gateway.cmd` 会执行受保护的停止、最终空闲核查、SQLite 备份、新程序维护期验证及恢复接单流程；保留原任务身份与凭据。详见 [升级说明](../gateway_update/README.md)。

## 普通设备

通过本机 MCP 的 `relay_usage` 默认查询自己最近 7×24 小时的统计，可将 `days` 设为 1..31，设为 1 则查看最近 24 小时。每个客户端凭据对应一个隔离身份；不能指定别人名字来读取他人的聚合。读取监控直接访问网关，不提交 Wind 数据任务，也不消耗新的原生调用预留。

```text
只使用 wind_terminal_relay，调用 relay_usage 查看我最近七天的任务、失败、排队、缓存和调用预留观测。区分 mock 与 native；未知值不要当成零，不要为检查用量另行取数。
```

## 管理员

首次部署会生成独立 `admin.json`，只能查看聚合报告，不读取其他客户端任务、参数或原始数据。旧网关用 `issue-admin` 添加此角色；保留旧网关、客户端和执行端凭据。以下命令都在已有配置的受控电脑操作，生成器不会打印凭据。

```sh
python relay_setup.py issue-admin --gateway .relay/gateway.json --url https://relay.example.com --output .relay/admin.json
python relay_admin.py --config .relay/admin.json --days 7
```

`relay.example.com` 是占位地址。添加管理员后需重载网关配置再查报告。使用本机虚拟环境的 Python；Windows 使用 `.venv\Scripts\python.exe`，Mac/Linux 使用 `.venv/bin/python`。

报告显示各设备和总计：窗口内接收任务、成功、失败、结果状态未知、排队与执行状态；另显示所有年龄任务的当前待处理数；native/mock 的计量分别列出，缺失计量的任务数量同时显示。时间窗为最近 days × 24 小时，UTC 表达，按入队时间划定统计群体，不是自然日账单。平均等待时间为入队到领取，执行阶段时间为领取到网关接收结果，不是纯 SDK 耗时。

另外的调用预留观测窗口按每次预留的执行端时间筛选，独立于上述任务入队群体。任务先排队再取数时，这两个窗口可能不同；默认观察最近 168 小时，不会在午夜或固定星期几清零。观测依赖执行端时间，只有结果回传之后云端才能看到这些事件。未回传及缺少逐次计量的旧任务保持未知，不能当成零；这仍不是整个 Wind 账户的完整扣量账单。

额度超限观察只记录本次失败任务中的 quota 错误，不把成功能力检查或回执中携带的历史错误重复记为新失败。最近失败时间不代表当前仍受限，也不能据它计算恢复时间。刷新规则与边界见 [QUOTA.md](QUOTA.md)。

## 增加和撤销设备

新增一台设备：

```sh
python relay_setup.py add-client --gateway .relay/gateway.json --client-id colleague2-win --url https://relay.example.com --output .relay/client-colleague2-win.json
```

撤销该设备：

```sh
python relay_setup.py revoke-client --gateway .relay/gateway.json --client-id colleague2-win
```

两者在网关重载配置后生效。管理命令有跨平台独占锁，防止两个管理员同时覆盖配置；不要绕过工具并发手工改写。旧身份保留历史任务归属，撤销后的 client_id 不能重新分配；换人或新设备使用新名字。撤销凭据不会删除旧回执，不会终止或重做已开始任务，也不会自动取消已排队任务。

## 限制与告警

网关 `queue_policy` 可以覆盖默认入队限制。默认每设备 5 个待处理任务、每设备每分钟 30 个新任务、全局最多 100 个排队任务，全局每分钟接收上限默认未配置。

达到入队上限返回确定未接收的拒绝，客户端显示 `accepted=false` 和可安全等待后重试的提示；不会要求轮询一个不存在的任务。提交响应丢失等不明确的网络故障则保留原 job_id，只核查原任务，不生成新任务重复取数。

本版本提供按需汇总，不创建定时通知或宣称已完成报警系统。可据当前待处理、不确定任务、失败、等待时间和配置预算的观测后续设置阈值；Wind 官方剩余额度、HTTP请求总数和精确 SDK 实际调用数仍为未知。各客户端分组不能覆盖普通本地 MCP、人工终端或其他程序的用量。

计量账本不随 24 小时原始结果清理而删除，只保留身份、任务归属、状态、时间和数字汇总。长时间使用后应另外制定账本保留及备份策略；本版本未自动压缩或删除历史计量。
