# Wind 中继管理台 0.3.1

本版修复左栏高亮：点击模块、手动滚动、返回与前进时都跟随当前位置。更新检查补充标准公共 CA 证书包，仍完整校验证书和域名；证书、DNS、超时与 HTTP 错误分别提示，最近检查时间也会记录失败尝试。安装后请按 F5 刷新页面。

把运行监控、设备管理和故障诊断放在一个本地页面。适用于已经部署 Wind 中继网关的 Windows 云电脑，复用已有 Python；不要求云电脑安装 Wind，也不要求重装 MCP。

## 安装或更新：只做三步

1. 在云电脑下载 `wind-relay-console-0.3.1.zip`，完整解压到一个**新文件夹**，例如桌面上的 `WindConsoleUpdate`。不要直接解压覆盖 `C:\WindRelay\app` 或 Python 文件夹。
2. 双击 `Update.cmd`，Windows 询问权限时选“是”。默认现有项目在 `C:\WindRelay\app`。看到 `Console 0.3.1 updated` 表示管理台本机版本检查通过。
3. 打开桌面的 **WindRelay-Console**。同一个页面就能看状态、管理设备、导出诊断。

更新只替换管理台文件和 `WindRelayMonitor` 任务，保留 `.relay`、数据库、已有接入文件、管理台密钥和日志。**不重启 WindRelayGateway、不升级网关或信创取数端，也不执行真实取数**。旧程序与任务定义备份在 `app\.console-updates\时间-编号`。更新中发现错误会尝试恢复旧程序与旧监控任务；如果仍失败，保留错误窗口与备份目录联系维护者。

桌面旧的 `WindRelay-Monitor` 网址仍可只读查看。日常请使用新的 **WindRelay-Console**，它会在本云电脑解锁设备管理。管理台任务后台运行，不需要弹出 PowerShell 窗口。

## 查看和更新实际部署信息

本版新增 **软件更新**：管理台启动时和每 6 小时从 Gitee 检查版本，你也可手动检查。选版本、点“下载并更新所选版本”并确认后才安装。确认前让同事暂停新任务；原接入文件保留。安装由独立任务执行，管理台重启后能继续读取结果。检查失败不影响现有服务，也不切换到 GitHub。完整说明见仓库的 `docs/ONLINE_UPDATES.md`。

页面的“实际部署信息”直接读取运行中的网关版本、构建号、轮转及限流配置；可点击“导出部署报告”发给维护者。旧网关没有上报版本就显示未报告，执行端版本没有证据就保持未知，不用记住每次改过什么。

要把旧网关本身升级，下载 **wind-relay-gateway-upgrade-0.1.3.zip**，解压到新文件夹，双击 **Upgrade-Gateway.cmd**；它会同时更新管理台。先让同事暂停新任务，保持 Wind、信创服务和 Tailscale 运行。参见更新包内 `gateway_update/README.md`。单独双击 `Update.cmd` 仍只更新管理台。

## 先看什么

- **云端网关**：检查本机网关与公网入口。公网检查从云电脑发出，不能保证其他设备的网络也畅通。
- **取数电脑**：最近心跳及 native/mock 模式。在线不等于 Wind 已登录；取数是否成功以实际任务及回执为准。
- **当前任务 / 最近任务**：区分排队、执行、失败、结果不确定。状态检查成功不会被算作真实取数成功。
- **用量观察**：滚动 7×24 小时，只展示后台实际记录的中继观测。官方额度上限、剩余量与恢复时刻未知；旧后台没有计量表时显示“未知”，不影响状态与任务监控，也不代表不能取数。更新管理台不会补齐旧计量记录。

## 添加一台新设备

1. 队列空闲时，在“设备管理”输入新名称，例如 `zhangsan-mac` 或 `lisi-win`，点击“添加设备”。名称用英文、数字、下划线或短横线，每台设备单独命名。
2. 下载这一行的 `client-设备名.json`。只单独发给对应使用者；文件就是访问钥匙，不能发群聊或放进 Git 仓库。
3. 按页面提示，先让使用者暂停提交新任务，确认队列没有排队、执行或不确定任务，再到任务计划程序将 **WindRelayGateway** “结束”后“运行”。不要手动再开一份网关。
4. 返回页面点击“核对生效”。新增凭据通过、旧探测身份仍可用，才会清除待重载提示。这一步只检查访问权限，不向 Wind 取数。
5. 再让对方按其他设备接入教程，把这个文件交给自己的 Codex / WorkBuddy 配置 `wind_terminal_relay`。消费设备只需要 relay 客户端，不需要本地 WindPy 或另装本地 Wind MCP。

新增或撤销都会先备份网关配置到 `.relay\console-backups`，保留原 worker / owner 等密钥。存在排队、执行、不确定或超时未处理任务时，界面禁止修改名单。保存失败时不要重新初始化；刷新名单并导出诊断，避免覆盖已经生成的文件。

## 撤销一台设备

点击该行“撤销”，输入完整设备名确认，再按页面提示重载网关并核对生效。重载前旧凭据仍可能访问。历史任务和接入文件保留，撤销过的名称不能再分配。管理台使用的 owner 探测身份不能在界面撤销。

管理台不会取消在途任务、删除故障标记或自动重做 Wind 查询；也不会替你强制结束网关。正常运行时不需要反复重载。

## 出问题，发什么给维护者

页面能打开：点“导出诊断包”。打不开：双击桌面的 **WindRelay-Diagnostics**。把得到的 ZIP 和“发生时间、当时做了什么”发给维护者。

诊断包包括：管理台版本和源码摘要、系统/Python/SQLite 版本、可读状态、经过筛选的错误类别与堆栈位置、近期管理操作的类别。**不包括 token、接入文件、原始异常消息、行情正文、查询参数或整个数据库**。不要另外把 `.relay` 或接入文件一起发送。

日志在 `app\monitor\logs\monitor.log`，每份约 1 MB，最多保留当前加 3 份轮转记录；写盘失败会在页面提示，导出仍尽量保留内存与可读状态。诊断导出不会重试取数，不会开启另一个日志写入进程。

## 管理台和网关是两件事

| 情况 | 处理 |
|---|---|
| 管理台打不开 / 停止刷新 | 查看或重新运行 `WindRelayMonitor`，导出诊断 |
| 网关本机检测失败 | 查看 `WindRelayGateway`，不要重复启动第二份 |
| 本机通、公网不通 | 检查网络、Tailscale 与 Funnel |
| 取数电脑离线 | 检查信创电脑开机联网、桌面登录和中继服务 |
| 有“不确定”任务 | 保留原 job_id，查执行端日志，不删 halt/inflight，不重复提交 |

服务只监听 `127.0.0.1:8766`。**不要用 Funnel 或反向代理开放管理台端口**。设备管理接口另有本机专用访问密钥，桌面入口自动读取，页面网址与日志不显示密钥。直接输入网址保持只读；关闭浏览器标签页不停止后台任务。

## 非默认目录 / 手工检查

从更新包目录打开管理员 PowerShell：

```powershell
.\Update.ps1 -AppDirectory 'D:\WindRelay\app'
```

只检查包与现有文件，不安装、不停服务：

```powershell
.\Update.ps1 -AppDirectory 'C:\WindRelay\app' -CheckOnly
```

该软件使用标准库，不捆绑 Wind、SDK、Python 或你的私有配置。软件发布与本机测试不等于已在你的云电脑更新完成，仍以实际更新窗口及页面显示为准。
