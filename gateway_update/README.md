# 现有云端网关，一键升级

适用于已经在 Windows 云电脑部署网关、使用 `WindRelayGateway` 任务、已有 `C:\WindRelay\app\.relay` 的用户。

## 你只需要这样做

1. 先让同事暂时停止提交新任务，确认管理台没有排队、执行或“不确定”任务。Wind、信创取数服务、Tailscale 保持运行。
2. 下载 **wind-relay-gateway-upgrade-0.1.1.zip**，完整解压到桌面的新文件夹。不要解压覆盖 app 或 Python。
3. 双击 **Upgrade-Gateway.cmd**，权限提示选“是”，等待显示 `DONE`。
4. 打开桌面的 **WindRelay-Console**，“实际部署信息”应显示网关 **0.1.1**、按设备轮流调度及正在使用的限流配置。然后让同事恢复使用。

原有 owner、colleague2、colleague3 等 JSON 继续使用，不需要重新发；执行端和各人客户端本轮不升级。管理台同时更新到 0.2.1。

如果提示有未完成任务或数据库不可读，会停止升级，不会自动取消、重做或删除这些任务。保留原 job_id，先解决原任务。

## 升级包会做什么

- 校验包内文件、工具契约和现有数据库，拒绝链接路径。先准备新程序和依赖，再停旧网关。
- Python 依赖已符合要求时复用原环境；否则在新网关目录创建独立环境并安装锁定依赖，需要联网。不会修改原虚拟环境。依赖准备失败时旧网关继续运行。
- 锁住设备配置修改；短暂停止网关后再次检查队列。若停止前刚有人提交任务，立即恢复旧网关，不迁移数据库。
- 用 SQLite 备份接口保存数据库，包含有效的 WAL 内容；保留任务、去重记录和凭据。
- 新代码放在 `app\.gateway-releases\版本-构建号`，不覆盖原 MCP、WindPy 或旧网关源码。
- 只切换 `WindRelayGateway` 的启动操作，保留任务原身份、已存密码、触发器与设置；失败时可以恢复旧启动操作，无需你重新输入 Windows 密码。
- 新网关先进入维护状态，期间不接单、不领取新任务。核对实际运行版本、构建号、轮转机制和原 owner 鉴权后才恢复接单。
- 恢复接单前失败：恢复旧数据库和启动操作。恢复接单后即使报告或窗口出错，也不回退数据库，避免抹掉新任务；此时应查看状态和部署报告。

旧程序和任务备份保留在 `.gateway-backups`，新版本程序在 `.gateway-releases`。不要手动清理维护标记、队列、去重表或备份。

## 自动保存的部署记录

升级时导出不含密钥的 JSON 到当前用户的“下载”目录，并在 `.relay\deployment-current.json` 保存本次记录。内容有：采集时间、网关版本和构建号、轮转和限流配置、工具契约版本、管理台版本、取数端在线/模式。

日后直接在管理台点击 **导出部署报告**，发送给维护者即可。它从当前运行的服务读取，不把“GitHub 已发布”或“磁盘文件已复制”当成“正在运行”。报告不含 token、接入文件、主机名、查询内容或整份数据库。

执行端未上报自身版本时明确写“未知”。网关升级不会使旧执行端自动具有逐次用量计量；可统计的新任务状态与完整 Wind 额度是不同概念。官方上限、剩余量仍未知。

## 非默认目录和只检查

从更新包目录打开 PowerShell：

```powershell
.\Upgrade-Gateway.ps1 -AppDirectory 'D:\WindRelay\app'
.\Upgrade-Gateway.ps1 -AppDirectory 'C:\WindRelay\app' -CheckOnly
```

`-CheckOnly` 不改文件或任务；它会读取数据库及环境。软件和离线测试发布不表示你的云电脑已经升级，以完成窗口及管理台的实际运行信息为准。
